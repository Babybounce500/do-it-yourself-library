Kapitel 3: Basis-Chatbot mit Memory

Ein einfacher Chatbot, der sich Konversationen merkt:

from langchain.chat_models import ChatOpenAI from langchain.memory import ConversationBufferMemory from langchain.chains import ConversationChain llm = ChatOpenAI(model="gpt-4", temperature=0.7) memory = ConversationBufferMemory() conversation = ConversationChain(llm=llm, memory=memory) # Starte deine Konversation response = conversation.run("Hallo, wer bist du?") print(response)
🎯 Memory-Typen: Buffer (einfach), Summary (intelligente Zusammenfassung), Entity (merkt sich wichtige Daten)

Kapitel 4: Custom Knowledge Base (RAG)

Gib deinem Bot Zugang zu eigenen Dokumenten:

from langchain.document_loaders import PDFLoader from langchain.vectorstores import FAISS from langchain.embeddings.openai import OpenAIEmbeddings # Lade deine PDFs loader = PDFLoader("deine_datei.pdf") docs = loader.load() # Erstelle Vector-Datenbank embeddings = OpenAIEmbeddings() vectorstore = FAISS.from_documents(docs, embeddings) # Suche nach relevanten Dokumenten results = vectorstore.similarity_search("Frage hier")
🚀 Real-World Use Case: Lade Kundendoku, FAQ oder Research-Papers hoch → Dein Bot wird zum Experten!

Kapitel 6: Optimierung & Monitoring

Mache deinen Bot besser:

⚡ Optimization-Tricks:
  • Nutze temperature=0.5 für faktische Antworten
  • Nutze temperature=0.9 für kreative Responses
  • Begrenzt Context-Window für schnellere Antworten
  • Cachen Sie häufige Fragen (sparen Kosten!)
# Tracking & Kosten-Monitoring import logging logging.basicConfig(level=logging.INFO) logger = logging.getLogger(__name__) def track_usage(prompt_tokens, completion_tokens): cost = (prompt_tokens * 0.0005 + completion_tokens * 0.0015) / 1000 logger.info(f"API Call Cost: ${cost:.4f}")

💡 PRO-TIPPS & INSIDER-TRICKS

🎯 Tipp 1: GPT-4 vs GPT-3.5 Trade-Off

Problem: GPT-4 ist 10x teurer (€0.03/1K vs €0.001/1K tokens)

Smart Lösung: Nutze GPT-3.5 für Prototyp & Testing, GPT-4 nur für Critical Features

Impact: 90% Kostenersparnis ohne Qualitätsverlust

🎯 Tipp 2: Request Caching für häufige Anfragen

Problem: Gleiche Fragen verschwenden API-Budget

Smart Lösung: Implementiere Redis-Cache oder In-Memory Caching

import functools import time @functools.lru_cache(maxsize=128) def get_cached_response(question: str): return client.chat.completions.create( model="gpt-3.5-turbo", messages=[{"role": "user", "content": question}] ) # Gleichzeitige Frage = 0 API-Kosten!

Impact: 50-70% Kostenersparnis + 10x schneller

🎯 Tipp 3: Context-Window Optimierung

Problem: Große Context = höhere Kosten & längere Latenz

Smart Lösung: Begrenzen Sie Konversationshistorie auf letzten 5-10 Messages

Impact: 30-40% schneller, 25% billiger

⚠️ HÄUFIGE ANFÄNGERFEHLER

❌ Fehler 1: API Keys in Source Code

Das passiert: Keys werden public auf GitHub, jeder kann APIs missbrauchen

✅ Lösung: Immer .env files nutzen + .gitignore

# .env OPENAI_API_KEY=sk-xxxxx # .gitignore .env # Code import os key = os.getenv("OPENAI_API_KEY") # ✅ Sicher!
❌ Fehler 2: Keine Rate-Limits setzen

Das passiert: Ein Bug → API-Calls in Schleife → €500 Rechnung in 1 Std

✅ Lösung: Immer Rate-Limiting + Spending Limits setzen

OpenAI Dashboard → Usage Limits → Setze €10/Tag max!

❌ Fehler 3: Zu große Context-Windows

Das passiert: Konversation läuft 1000 Messages → Token explodieren

✅ Lösung: Limit auf letzte 20 Messages, ältere archivieren

🔧 TROUBLESHOOTING GUIDE

Problem 1: "401 Unauthorized" Error

Symptom: OpenAI API gibt 401 zurück

Ursache: API-Key ist falsch, abgelaufen oder in Headers vergessen

Lösung 1 (Quick): API Key auf openai.com neu generieren

Lösung 2 (Tief): Prüfe ob .env richtig geladen wird

# Debug: API Key prüfen import os print(os.getenv("OPENAI_API_KEY")) # Sollte nicht None sein!
Problem 2: Response Timeout (Requests hängen)

Symptom: API antwortet nach 30+ Sekunden

Ursache: Große Context, Model Overload, Network Issues

Lösung: Timeout erhöhen + Streaming aktivieren

# Mit Timeout + Streaming response = client.chat.completions.create( model="gpt-3.5-turbo", messages=messages, timeout=60, # Erhöht von default 30 stream=True # Streaming = schnellere erste Tokens )
